# Alembic Skill

## Purpose
Manage safe, reviewable PostgreSQL/PostGIS schema migrations.

## Rules
- Every schema change must have an Alembic migration.
- Review autogenerated migrations manually.
- Never blindly run destructive autogenerated changes.
- Test both upgrade and downgrade where practical.
- Preserve existing data during renames/type changes.
- Use explicit data migrations for transformations.
- Enable required PostgreSQL extensions such as PostGIS through migrations when appropriate.
- Create/drop spatial indexes explicitly when required.
- Handle foreign keys, constraints, enums, defaults, and timestamps deliberately.
- Never point development migrations at production accidentally.
- Keep migration history linear/understandable and resolve merge conflicts carefully.

## SIH safety
Back up important data before destructive production migrations and run migrations as an explicit deployment step.
